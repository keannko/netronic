# Підготовка релізу SKIFTECH

## Перевірка

У `api`: `npm ci`, `npm test`. У `skft`: `npm ci`, `npm run lint`, `npm run build`.

## Конфігурація

- Для API встановити `NODE_ENV=production`, `CLIENT_URL` (точний origin фронтенду), два різні `JWT_ACCESS_SECRET` і `JWT_REFRESH_SECRET` (щонайменше 32 символи кожен) та `SKIFTECH_STORAGE_FILE` (постійний записуваний шлях). При першому запуску з порожнім сховищем також потрібні `SKIFTECH_ADMIN_EMAIL` і `SKIFTECH_ADMIN_PASSWORD` (щонайменше 12 символів). Див. [приклад API змінних](./api/.env.example).
- Для фронтенду встановити `VITE_API_URL` перед збіркою. URL має вести на API; у Vite dev server `/api` працює через proxy. Див. [приклад фронтенд змінних](./skft/.env.example).
- Налаштувати хостинг SPA так, щоб `/cabinet` та інші маршрути повертали `index.html`. Для API використати HTTPS і зберігати файл даних та його резервні копії поза тимчасовим каталогом контейнера.

## Перед відкриттям доступу

- Замінити тестові адреси `staff01@example.test` … `staff08@example.test`, їхні демонстраційні паролі та початкові паролі `123`. API відхиляє production запуск, якщо знайде ці облікові записи чи початковий пароль.
- Відкликати Telegram bot token, який раніше зберігався у фронтенд коді. Невикористовуваний файл видалено з поточного дерева, але токен міг залишитися в історії Git.
- Перевірити реальні дані співробітників, дати народження, зображення та місячні звіти. Локальний файл `api/.local/data.json` не є частиною репозиторію і не переноситься під час збірки.
- Вирішити долю маршрутів `/products`, `/orders` і `/blog`: API для них наразі повертає порожній результат на GET та `501` для змін. Повний реліз відповідних розділів сайту потребує окремого підключення сховищ і перевірки функцій.
- Сесії авторизації зберігаються в пам’яті процесу. Перезапуск API завершує поточні сесії; горизонтальне масштабування потребує спільного сховища сесій і заміни локального JSON сховища.

Production запуск свідомо не використовує тестові облікові записи за замовчуванням. Новий адміністратор створюється з параметрів середовища та зберігається у файлі даних.
